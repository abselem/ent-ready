# Команда и результаты доработки ent-ready

Дата: 23 октября 2026 года. Рабочий проект: `C:\Users\HomePC\ent-ready-master`.

## Команда внедрена

В `.codex/agents/` находятся пять проверенных TOML-конфигураций: `architect`, `frontend`, `backend`, `tester`, `business_analyst`. Корневой `AGENTS.md` задаёт процесс: продуктовая идея → требования и технический план → разработка → независимое тестирование → интеграция. Модели наследуются от основного чата. Исследование аналогов не разрешает автоматически внедрять новые функции.

## Выполнено

- Серверные проверки доступа к группам, урокам, тестам и персональным генерациям. Владелец сохраняет доступ к своим черновикам; публичные материалы и явные разрешения проверены отдельно.
- Безопасные ответы API без хешей паролей и Telegram ID; приглашения группы доступны владельцу.
- Проверка активной сессии, блокировки и актуальной роли; отзыв access/refresh при выходе и восстановлении; повторное подтверждение при смене пароля.
- Атомарные попытки/потребление OTP и ротация refresh; дополнительные ограничения частоты verification endpoints.
- Изоляция кеша и запоздавших ответов между аккаунтами; UI выхода отзывает серверную сессию.
- Генераторы используют только вопросы с явным разрешением автора. Миграция `024_test_generation_access.sql` добавляет разрешение с default false и владельца персональной генерации. В редакторе банка есть соответствующий переключатель.
- Серверные ограничения времени и проверки принадлежности вопросов/вариантов попытке; идемпотентное завершение.
- Небезопасная Telegram-привязка отключена ответом 410 до реализации подтверждённого одноразового связывания.
- Production не допускает неявный OTP log sender. Локальный запуск использует явный override `APP_ENV=development`.
- Next.js обновлён до 16.4.3, связанные зависимости обновлены, PDF worker синхронизирован; Docker использует Node 22. Неиспользуемая зависимость next-pwa удалена. Добавлены Docker ignore-файлы для секретов и локальных артефактов.

Изменения пакетов основаны на npm audit и публичных первичных предупреждениях [Next.js](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw) и [PDF.js](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j). Наличие advisory не означает, что конкретная конфигурация приложения была успешно эксплуатирована.

## Ограничения и дальнейшие задачи

- Это исправление подтверждённых находок и регрессионные проверки, а не доказательство отсутствия всех уязвимостей. Полный браузерный E2E-аудит и нагрузочная проверка не выполнялись.
- Telegram linking требует отдельного безопасного flow; сейчас отключён. Восстановление passwordless аккаунта доступно через email reset API, отдельного нового UI не добавляли.
- Вопросы старого банка остаются закрыты генератору, пока автор явно не разрешит их использование. Массовое открытие вопросов не выполнялось.
- Авторизация между несколькими вкладками автоматически не синхронизируется. Offline-выход очищает локальное состояние, но не гарантирует отзыв серверной сессии до восстановления сети.
- Существующая форма добавления ученика отправляет `phone`, тогда как сервер ожидает `user_id`; это отдельный ранее существовавший дефект.
- Для production дополнительно проверить доверенные proxy/IP rate limiting, ограничения распаковки DOCX и актуальность Go-зависимостей; эти направления не следует считать закрытыми текущим набором проверок.
- В local development OTP могут записываться в логи. Не использовать локальный override с production-данными.
