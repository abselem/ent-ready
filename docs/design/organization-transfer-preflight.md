# Подготовка переноса — UX A2.1

Дата: 02.11.2026. Контракт: `docs/requirements/organization-isolation-a2.md`. Небольшое дополнение существующего экрана организаций, без нового визуального языка. Пользователь — active owner/admin выбранной организации, желающий проверить зависимости собственных учебных материалов перед будущим ручным переносом. Исследования пользователей не проводились.

## Граница функции

Предварительная проверка только читает данные. Она не переносит материалы, не меняет членство, публичность, владельца или права. A2.1 не подтверждает tenant isolation. Общие материалы остаются в отдельном каталоге. API возвращает `execution_allowed:false` и `tenant_enforcement_ready:false` даже при пустом списке blockers.

## Карточка в существующем экране

Внутри выбранного пространства после «Настроек», до «Участников» добавить Card с h3 «Подготовка переноса». Рендерить и запрашивать данные только для owner/admin после успешной загрузки detail. На экране без выбранной организации карточки нет.

Постоянный текст под заголовком:

> Выберите собственную группу, урок или тест и проверьте связанные данные перед ручным переносом. Материалы «Для всех» останутся в отдельном общем каталоге. Проверка не переносит данные. Фактический перенос пока недоступен.

Форма:

1. Native select с label «Что проверить»: «Группу» → group, «Урок» → lesson, «Тест» → test. Стартовое значение group; оно не выбирает материал автоматически.
2. Native select с label «Материал»: placeholder «Выберите группу/урок/тест», варианты из соответствующего candidates массива по title. Значение — id, не название. Чтобы различать одинаковые названия, добавить « · №ID» к вариантам с дубликатами. Полное название выбранного материала повторить ниже в переносимой строке, если native select его обрезает.
3. При `has_more[type]`: «Показаны последние 100 материалов этого типа. Список неполный». Не обещать доступный поиск или загрузку следующей страницы — их нет в контракте. Не превращать отсутствие элемента среди 100 в вывод о его отсутствии у пользователя.
4. Button «Проверить перенос», во время POST «Проверяем…». Disabled при пустом материале, загрузке candidates или активном запросе. Отправлять только resource_type/resource_id.

Без кнопки «Перенести», apply/подтверждения переноса, чекбокса согласия на перенос, фиктивного шага выполнения или прогресс-бара миграции. Нет destructive-action confirmation: действие не меняет данные.

## Отчёт

Результат размещается внутри той же Card под формой, с h4 «Предварительная проверка». Появление объявить коротким role=status «Предварительная проверка завершена»; не делать весь длинный отчёт live-region.

- Источник: тип, title и №ID из response.resource.
- Назначение: полное имя выбранной организации. Проверить response.target_organization_id против текущего ID до рендера.
- «Снимок данных: …» из as_of, формат ru-RU с явной зоной или указанием локальной зоны пользователя. Без «актуально навсегда»: текст «Зависимости могли измениться после проверки. Для обновления запустите проверку ещё раз».
- Количества как definition list: «Группы», «Уроки», «Тесты», «Вопросы», «Контексты». Нули показывать явно. Пояснение: «Учтены только ваши объекты в выбранном наборе». Не выдавать counts за полный объём школы или оценку длительности переноса.
- При blockers.length > 0: заголовок «Найдены препятствия», далее список `message`, рядом `count` («Количество: N»). Код можно не показывать в обычном интерфейсе. Длинные сообщения переносятся. Не добавлять предположительные имена/ID чужих данных, которых нет в ответе.
- При пустом blockers: «В проверенных зависимостях препятствий не найдено. Перенос всё равно недоступен». Нейтральная surface/muted, без зелёного success, галочки «Готово» или процентов готовности.
- Постоянная нижняя строка отчёта: «Фактический перенос недоступен. Изоляция учебных данных организаций ещё не включена». Отображать API notice как текст, не HTML, не заменяя этим собственное постоянное пояснение.
- Ответ с любым readiness flag, отличным от false, не превращает UI в готовый перенос. Считать несоответствием контракта: «Не удалось подтвердить результат проверки. Обновите страницу или повторите позже», отчёт не рендерить. Самостоятельно включать применение запрещено.

## Состояния и восстановление

| Состояние | Интерфейс |
|---|---|
| Candidates loading | AsyncState «Загружаем ваши материалы…»; выбор материала и проверка disabled |
| Candidates network/5xx | «Не удалось загрузить материалы» + «Повторить»; не показывать пустой список как успешный результат |
| Пустой выбранный тип | «У вас пока нет групп/уроков/тестов для проверки»; действие disabled; переключение типа доступно |
| POST pending | Loading Button, прежний отчёт убран при запуске; текст «Проверяем связанные данные…» |
| POST 400 | «Не удалось проверить выбранный материал. Обновите список и выберите его снова»; не стирать настройку организации |
| POST 404 | «Материал или пространство недоступны. Обновите список и выберите материал снова»; старый отчёт скрыть, refresh candidates/detail через существующую обработку |
| POST/candidates 403 | «Для проверки нужны права владельца или администратора пространства»; убрать форму/отчёт, обновить detail, не обходить ограничение глобальной ролью teacher |
| POST timeout/network/5xx | «Не удалось получить результат проверки. Данные не переносились. Повторите проверку»; сохранить текущие type/resource, показать retry без автоматического цикла |
| Истёкшая сессия | Общий auth-flow; отчёт очищается вместе с данными аккаунта |

Успешный HTTP 200 — только успешная предварительная проверка, не успешный перенос. Сообщение API ошибки — безопасный текст, не необработанный HTML/stacktrace.

## Гонки и смена контекста

- Candidate query key включает user ID, sessionVersion и organization ID; не использовать keepPreviousData для карточки другой организации.
- Preflight фиксирует user/session/org/type/resource/request sequence в момент отправки. Показывать результат только при совпадении со всеми текущими значениями. Query key либо явная request-generation проверка — выбор frontend.
- Смена организации, аккаунта, типа или материала сразу скрывает предыдущий отчёт и его ошибку. Не оставлять старые counts под новым названием. Смена типа сбрасывает resource ID в placeholder, даже если числовой ID совпадает между типами.
- Можно оставлять селекторы доступными при pending, только если late-response guard реализован; иначе временно блокировать селекторы карточки. Организацию пользователь всё равно может переключить, поэтому server response guard обязателен в обоих вариантах.
- Если candidates обновились и выбранный ID исчез, сбросить его и отчёт. Не подставлять первый материал автоматически.
- GET/POST проверки не считаются несохранёнными настройками: уход с этой карточки не должен порождать предупреждение о потерянном переносе. Existing guard настроек организации продолжает работать отдельно.

## Адаптивность и доступность

Использовать Card/Button/AsyncState, control-field и globals.css. На телефоне все поля и кнопка в одну колонку, кнопка доступна без горизонтальной прокрутки; от md два select в ряд, действие ниже. Counts — 2 колонки на телефоне, 3–5 при достаточной ширине; альтернативно обычный переносимый definition list. Никаких широких таблиц.

Label связан с select, состояние disabled не заменяет объясняющий текст. Pending: aria-busy на области, короткий status. Ошибка: role=alert, фокус не переносить неожиданно в длинный список. Кнопки не ниже 44px, видимый focus-visible, длинные заголовки/сообщения — break-words. Полное название источника и организации доступно текстом. Не передавать причину препятствия только цветом. Соответствие стандартам доступности требует проверки в браузере и не заявляется по спецификации.

## Приёмка tester/frontend

1. Owner/admin открывает выбранную организацию, выбирает каждый из трёх типов и собственный материал по названию, получает snapshot/counts/blockers.
2. Пустой список и has_more честно отличаются от ошибок; нет вымышленных дополнительных страниц/поиска.
3. Пустой blockers не показывает «Готово к переносу»; оба false flags и постоянное ограничение сохраняются.
4. Во всех состояниях отсутствует действие фактического применения.
5. Задержанный ответ организации A/источника X не появляется после перехода в B/Y либо смены аккаунта.
6. 403/404/timeout убирают невалидный отчёт, дают понятное восстановление, не стирают draft настроек организации.
7. При ширине 360px и keyboard-only все поля/действия доступны, длинные названия/препятствия не создают горизонтальную прокрутку.

Ревью работающего UI после реализации отдельно. Сейчас документ основан на контракте и исходниках A1; браузер не использовался.

## Ревью реализации A2.1 — 02.11.2026

Прочитаны `teacher/organizations/transfer-preflight.tsx`, интеграция в `teacher/organizations/page.tsx` и типы/методы в `lib/organizations-api.ts`. Исходники не менялись. Браузерная и визуальная проверка NOT RUN: localhost недоступен по разрешениям, обход не выполнялся.

Существенных расхождений со спецификацией по исходникам не найдено:

- Карточка расположена между настройками и участниками, родитель рендерит её только при editable owner/admin. Постоянный текст прямо ограничивает проверку чтением данных и сохраняет общий каталог отдельно.
- Select имеют связанные label/id, placeholder и объяснение пустого выбранного типа; has_more показан как неполный список. Дубликаты title различаются №ID, полное выбранное название повторяется переносимым текстом.
- Нет apply-действия и положительного статуса готовности. `validReport` требует оба readiness flag строго false, соответствие org/type/resource, валидные counts/blockers/as_of. Не соответствующий контракту ответ превращается в ошибку без отчёта.
- Отчёт содержит источник, организацию, снимок с явной UTC-зоной, counts, ограничения набора и blockers с count. Пустые blockers показаны нейтрально с фразой о недоступности переноса. Notice рендерится обычным React-текстом.
- Смена type/resource очищает отчёт и ошибку с увеличением request revision. Поздний success/error сравнивается с revision; unmount также её меняет. Ключ формы включает user/session/org и набор candidate IDs. Изменение состава candidates инвалидирует выбор; выбранный чужой контекст не используется повторно.
- Pending/error/403/404 предусмотрены, запросы не повторяются автоматически, 403 скрывает форму и обновляет detail. Guard несохранённых настроек не зависит от предварительной проверки.
- Мобильная компоновка по исходникам: поля в одну колонку до md, min-w-0, break-words, counts grid 2/3/5, стандартные touch-размеры. Реальная ширина 360px, скринридер и keyboard-flow остаются непроверенными.

Неблокирующее текстовое улучшение: для поля отчёта «Источник» использовать именительный падеж «Группа», а не label выбора «Группу». На функциональность и запрет переноса это не влияет.

`git diff --check` для проверенных файлов: PASS. Build/lint и сценарии с реальным сервером мной не запускались. Проверка серверного разграничения и READ ONLY транзакции относится к независимому tester/архитектору.
