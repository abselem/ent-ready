# Рабочие пространства — UX/UI A1

Дата: 02.11.2026. Основание: BRD v1.0 и постановка координатора. Спецификация для первого технического этапа, без переноса учебных данных в организации.

## Пользователь и границы

Пользователь A1 — зарегистрированный преподаватель, который готовит рабочее пространство школы или своей практики. Цель — создать организацию, проверить её настройки и выбрать организацию для дальнейшей настройки. Существующий личный кабинет продолжает работать отдельно.

Наблюдение по исходникам: есть Nav с пятью разделами, Card, Button, Input, PageHeader и AsyncState; установлены светлые/тёмные семантические токены. Исследование с пользователями не проводилось. Предположение: отдельный экран настроек достаточно понятен для первого этапа, если граница с личным обучением написана явно.

Не показывать фиктивные курсы, лимиты, родительские связи, приглашения и перенос материалов. A1 не означает полноценную изоляцию существующего учебного процесса по организациям.

## Навигация и структура

- `/teacher/profile`: отдельная Card «Рабочие пространства» после блока личных данных. Текст: «Создайте организацию и настройте её параметры». Ссылка «Управлять рабочими пространствами» на `/teacher/organizations`.
- Сохранить пять существующих пунктов общей Nav. Не добавлять шестой длинный пункт в мобильную нижнюю панель. Путь через Профиль одинаков на телефоне и компьютере. На новом экране предоставить ссылку «← Профиль».
- `/teacher/organizations`: page-shell; PageHeader «Рабочие пространства», описание «Настройте организацию для школы или частной практики», основная кнопка «Создать пространство».
- Под заголовком постоянное нейтральное пояснение: «Здесь настраиваются организации. Группы, уроки и тесты вашего личного кабинета пока не перенесены в рабочие пространства». Использовать Card или bg-accent, без тревожного предупреждения.
- Список организаций — отдельные Card: полное название с переносом, роль текстом, timezone и язык, кнопка «Настроить». Выбранная карточка имеет border-primary и текст «Выбрано для настройки»; одного цвета недостаточно.
- Ниже списка выбранное пространство: heading с названием, карточка «Настройки», далее «Участники» для owner/admin. Обычным участникам — параметры read-only и текст своей роли, без запроса скрытого списка участников.
- Создание раскрывается в отдельной Card над списком, не модальное окно. «Отмена» закрывает форму; незаполненные значения не превращаются в данные организации.

## Формы и поведение

Поля создания и настроек: «Название», «Часовой пояс», «Язык рабочего пространства», «Система оценивания». Повторно использовать Input и native select с control-field; явные label/id.

- Название: обязательное, пробелы по краям обрезаются; максимальная длина согласуется с backend. Сообщение: «Введите название рабочего пространства».
- Часовой пояс: значение Asia/Qyzylorda по умолчанию. Редактируемая строка IANA с примером и серверной проверкой; не использовать неоднозначные UTC-смещения вместо зоны.
- Язык: «Русский» → ru, «Қазақша» → kk. Подпись «Язык рабочего пространства не меняет язык текущего интерфейса» до отдельной локализации UI.
- Оценивание: «Баллы» → points; «5-балльная» → 5; «10-балльная» → 10; «100-балльная» → 100. Это настройка организации, не преобразование существующих результатов.
- Создание: «Создать пространство» → «Создаём…»; блокировать повторное отправление. После успешного ответа выбрать новый ID, показать detail из серверного ответа/повторного GET и сообщение role=status «Рабочее пространство создано».
- Настройки: кнопка «Сохранить настройки», disabled если нет изменений; при ошибке сохранять ввод. После PATCH сообщение «Настройки сохранены», без кратковременного исчезновения формы.
- Переключение не сохраняет несохранённую форму автоматически. Если есть изменения, предупредить: «Есть несохранённые настройки. Перейти к другому пространству без сохранения?» и дать остаться.
- Сохранённый ID организации — только предпочтение клиента. После загрузки списка проверить ID; не показывать stale detail другого ID. Список/деталь/участники в cache привязаны к пользователю и organization ID. При смене аккаунта очищать выбор либо иметь ключ пользователя.
- В A1 название выбора — «Выбрано для настройки». Нельзя менять подписи Nav на имя организации или создавать впечатление, что существующие группы автоматически стали её данными.

Участники: простая вертикальная list, имя и фамилия, роль (Владелец/Администратор/Преподаватель/Ученик/Родитель). При отсутствии имени — «Участник №ID». Не отображать email/телефон. Пустой ответ — «Участников пока нет»; ошибку загрузки не выдавать за пустой список. Управление участниками и отправка приглашений в A1 отсутствуют.

## Состояния

| Состояние | Интерфейс и восстановление |
|---|---|
| Первый GET списка | AsyncState loading «Загружаем рабочие пространства…», форму не заполнять данными чужого кэша |
| Пустой список | «Рабочих пространств пока нет», пояснение и кнопка создания |
| Ошибка списка | AsyncState error «Не удалось загрузить пространства» + «Повторить»; не сбрасывать draft создания |
| Загрузка детали | Список остаётся, detail loading, поля старого пространства скрыты/disabled |
| Нет выбранного ID | «Выберите пространство для настройки» |
| Detail 404 / членство прекращено | «Пространство недоступно», очистить выбранный detail, обновить список; не раскрывать существование чужой организации |
| Роль без редактирования | read-only настройки, «Изменять настройки могут владелец и администратор» |
| PATCH 403 после смены роли | Сохранить локальный текст, показать «Недостаточно прав для сохранения. Обновите сведения о пространстве», повторно GET; не оставлять активную кнопку изменения |
| POST/PATCH validation | Ошибка рядом с полем и понятное общее сообщение, фокус на первой ошибке |
| Timeout POST | «Не удалось подтвердить создание. Обновите список перед повторной попыткой»; не повторять POST автоматически и не обещать идемпотентность, пока её нет в API |
| Timeout PATCH | «Не удалось подтвердить сохранение. Проверьте настройки и повторите», ввод сохранён |
| Истёкшая сессия | Общий auth-flow; не показывать защищённые данные после выхода |

## Адаптивность и доступность

Сохранить токены globals.css, Card rounded-2xl/p-5/md:p-6, Button min-h-11, поля не ниже 44px. PageHeader с переносом; кнопка создания на телефоне может занимать всю ширину. Список максимум в две колонки от md, формы одна колонка на телефоне/две на desktop. Между основными блоками 24px, внутри формы 16px. Длинные названия переносить, не обрезать единственную доступную версию названия.

Не вводить новую библиотеку/цветовую тему. Сохранить focus-visible, label, aria-describedby для ошибки и role=status/alert. Выбор организации выполняется button с aria-pressed либо обычной явной кнопкой «Настроить», не кликабельным div. Заголовки h1 → h2 → h3 последовательны. Нижняя Nav не перекрывает submit благодаря mobile-nav-space. Фокус после раскрытия создания — в название, после закрытия — на кнопку открытия. Проверка соответствия стандартам доступности пока не выполнена.

## Приёмка и проверка

1. Профиль → рабочие пространства доступен на ширине 360px и desktop; Nav остаётся читаемой.
2. Создание валидации → успех → выбор → GET detail → редактирование → PATCH success проходит без перезагрузки всей страницы.
3. Организации A/B имеют независимые draft/detail; запоздалый ответ A не отображается под заголовком B.
4. Повторный вход другой учётной записью не показывает имя и участников предыдущей организации.
5. Read-only участник не видит редактор и members; серверный отказ обрабатывается явно.
6. Ошибка/timeout не стирает введённый текст, не выдаётся за успешное действие.
7. Пояснение о личных учебных данных видно в обычном и пустом состоянии, выбранная организация не меняет существующие API групп/уроков/тестов.
8. Keyboard-only: все поля и действия доступны, видимый фокус, сообщения связаны с полями; при 360px нет горизонтальной прокрутки.

Дизайн-ревью работающего интерфейса назначить после реализации. Этот документ основан на чтении исходников; браузерная проверка ещё не проводилась.

## Ревью реализации A1 — 02.11.2026

Проверены исходники `frontend/src/app/teacher/organizations/page.tsx`, карточка в `teacher/profile/page.tsx`, guard в `components/nav.tsx`, `lib/organizations-api.ts` и смена аккаунта в `store/auth.ts`. Это read-only ревью кода, не визуальная или браузерная проверка.

Блокирующих расхождений со спецификацией по проверенным исходникам не найдено:

- Вход через карточку профиля и обратная ссылка реализованы; общая Nav не расширена. Постоянное пояснение об отдельности учебных материалов присутствует. Выбор подписан «Выбрано для настройки».
- Используются существующие компоненты/токены, сетка одна колонка → две от md, перенос длинных названий и touch-размеры. Реальное отсутствие overflow при 360px ещё требует браузера.
- Поля имеют label, ошибки связываются Input с полем; есть status/alert, фокус на названии при раскрытии и возврат на кнопку при отмене, кнопка выбора имеет aria-pressed. Keyboard-flow и screen reader в работающем браузере не проверялись.
- Предусмотрены загрузка/пустое состояние/ошибка списка, detail 404, save 403, read-only роль и отдельная ошибка members. Список участников не запрашивается для read-only ролей; email/телефоны отсутствуют в интерфейсе.
- POST не повторяется автоматически; неоднозначная сетевая ошибка требует обновить список перед повторением. Draft не стирается после обычной ошибки сохранения. Guard для ухода и beforeunload учитывают несохранённые настройки.
- Query keys содержат user ID и sessionVersion; выбор не меняет существующие запросы учебных материалов. При выборе другого ID старые detail/members удаляются перед новым запросом. Факт серверной изоляции оценивает tester/архитектор, это ревью не заменяет их проверку.

Неблокирующее улучшение следующего прохода: после изменения уже сохранённого поля скрывать прежнее сообщение «Настройки сохранены», чтобы оно не оставалось рядом с новым несохранённым draft. Текущая активная кнопка сохранения и guard поддерживают рабочий сценарий, но постоянное сообщение может восприниматься как подтверждение новых правок.

`git diff --check` для проверенных файлов выполнен: PASS. Build/lint мной не запускались. Для полной приёмки остаются браузерные проверки 360px/desktop, keyboard-only и реальные ответы ошибок/смены аккаунта.
