# BRD A1 — результат и проверки

Дата: 02.11.2026. Реализован первый подэтап, весь BRD не завершён.

## Что работает в коде

- `/teacher/profile` → «Рабочие пространства» → `/teacher/organizations`.
- Создание организации, атомарное назначение создателя владельцем, список своих организаций и выбор для настройки.
- Настройки названия, часового пояса IANA, языка ru/kk и шкалы оценивания.
- Состав организации для owner/admin без email и телефонов.
- Проверки активного членства и роли на сервере; чужая или неактивная организация возвращает 404.
- Сохранение ввода при ошибке, защита от ухода с несохранённой формой, отсутствие автоматического повторения POST.
- Частичный PATCH сохраняет независимые параллельные изменения.

Права owner/admin/teacher/student/parent относятся только к организации. Глобальная роль существующей учётной записи не меняется. Создавать организации в A1 могут только существующие teacher — временное ограничение этого этапа.

## Генерация SQL

`sqlc generate -f sqlc.organizations.yaml` (sqlc v1.31.1). Источники `db/organization_queries/`, результат `db/organizationsqlc/`. Старые SQL-источники и generated имеют ранее существовавшие расхождения; отдельная конфигурация предотвращает посторонние изменения legacy API. Существующие `db/sqlc/` не изменены.

## Ограничения и следующий этап

A1 изолирует только организации и их состав. Группы, уроки, тесты, файлы и результаты пока остаются в прежнем личном кабинете; UI прямо сообщает это. Полную tenant isolation не объявляем. Следующий обязательный этап A2 — привязка учебных агрегатов к организациям, миграция существующих данных по утверждённой политике и негативные тесты всех обходных маршрутов. Затем — приглашения, учебный цикл ДЗ → проверка → дневник, родители и остальные требования согласно плану.

Сохранность картинок после Railway redeploy остаётся отдельной нерешённой инфраструктурной задачей. Локализация интерфейса, преобразование старых оценок, приглашения, родительские связи и тарифы в A1 не реализованы.

Новая миграция `025_organizations.sql` проверена только локально на тестовой БД. В production не отправлялась. `main.go` автоматически применяет миграции при старте, поэтому push с автодеплоем означает изменение production-схемы. Согласно AGENTS.md публикация и production-миграции требуют разрешения пользователя на этот конкретный результат.
