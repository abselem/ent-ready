# A2 — ручной перенос и изоляция учебных данных

## Решения пользователя

02.11.2026: существующие группы, уроки и тесты переносить вручную в выбранные организации. Материалы «Для всех» оставить в отдельном общем каталоге. Автоматического backfill всех ресурсов в одну школу или создания организаций для преподавателей не выполнять.

## A2.1: предварительная проверка без изменения данных

Первый безопасный срез — выбор собственных материалов и получение отчёта о зависимостях перед будущим переносом. Пока не реализованы все tenant guards, операция фактического переноса недоступна. Это не tenant isolation и не завершённый A2.

Все маршруты требуют JWT и active owner/admin целевой организации, проверяемые на сервере. Неактивное/чужое членство —404; известный участник без прав —403. Глобальная роль не заменяет роль организации. Источники — только собственные ресурсы actor, не общедоступные чужие материалы.

- `GET /api/v1/organizations/:id/transfers/candidates`: `{groups:[{id,title}],lessons:[{id,title}],tests:[{id,title}],has_more:{groups:boolean,lessons:boolean,tests:boolean}}`. Максимум100 на категорию, детерминированно ID DESC, запросить101 для has_more. Название группы отображается как title. Не возвращать учеников, чужие ресурсы, приглашения, контакты и содержимое ответов.
- `POST /api/v1/organizations/:id/transfers/preflight`: строгое тело `{resource_type:"group"|"lesson"|"test",resource_id:positiveInt32}`; неизвестные поля/null/дополнительный JSON/тело>4KB запрещены400. Чужой/отсутствующий корень —404 без частичного отчёта. Повторные POST ничего не изменяют.

Ответ200: `{resource:{type,id,title},target_organization_id,as_of,execution_allowed:false,tenant_enforcement_ready:false,counts:{groups,lessons,tests,questions,contexts},blockers:[{code,count,message}],notice}`. Отсутствие blockers не является разрешением или доказательством готовности к переносу. Нет apply endpoint, confirmation token, автоматического создания membership, копирования материалов или изменения публичности.

Снимок строится в READ ONLY REPEATABLE READ транзакции; active manager membership перепроверяется в этом снимке. Корень group включает связанные собственные lessons/tests; чужие дочерние материалы дают обезличенный blocker. Отдельный lesson/test со связанной группой требует проверки корня group. Questions включают связи через test_questions и старый questions.test_id; contexts выводятся из выбранных вопросов. Чужие вопросы/контексты и ссылки за пределы выбранного набора обозначаются blocker без чужих ID/названий/текстов. Counts — только принадлежащие actor объекты.

Проверки blocker: опубликованный общий каталог; история test_attempts/lesson_views/ENT; shared questions и legacy test_id вне набора; включённая generation_allowed; context с вопросами вне набора; участники группы без active membership целевой организации; lesson_access вне выбранного набора/целевого состава; чужой владелец зависимого материала; изображения/файлы, требующие отдельной миграции прав и постоянного хранения. Достаточно обнаружения проблем по данным БД. Не выполнять HTTP-запросы по ссылкам, чтение локальных путей из пользовательского контента или перенос файлов.

UI: в выбранном пространстве отдельная карточка «Подготовка переноса», пояснение о ручном переносе и сохранении общего каталога. Выбор типа и собственного материала по названию, кнопка «Проверить перенос». Снимок, количества и понятные причины блокировок, постоянный текст «Проверка не переносит данные». Не показывать кнопку «Перенести», состояние «Готово к переносу» или обещание полной изоляции. Ошибки/пустой список/has_more отображать честно; при смене организации/аккаунта убрать старый отчёт и не принимать поздний ответ от предыдущего выбора.

## Дальнейший A2.2 — обязательные условия фактического переноса

Нужны nullable organization_id на учебных агрегатах, целостность межобъектных ссылок, active memberships/enrollments и явные scoped API. Все legacy прямые чтения/изменения/списки, блоки, вопросы, варианты, attempts/reviews, random tests/ЕНТ и доступ к файлам должны исключать обход tenant scope. Общий каталог — отдельная область, а не утечка org-private. Исторические попытки и просмотры не перемещать без отдельной согласованной политики. Новые migrations и backfill проверять на отдельной БД; production только после review и разрешения пользователя.

Публиковать transfer endpoint до выполнения этих условий нельзя: старые API с creator_id могли бы сохранить доступ после отзыва членства. A2.1 не меняет существующие access predicates и потому не создаёт таких частично перенесённых данных.
