# A2.1 — подготовка ручного переноса

Дата: 02.11.2026. Результат: реализована предварительная проверка выбранных материалов. Фактический перенос и полная tenant isolation ещё не реализованы.

## Поведение

В настройках выбранной организации owner/admin видит карточку «Подготовка переноса»: тип материала, список собственных названий и кнопку проверки. Показываются до100 последних объектов каждого типа с честным `has_more`; чужие материалы не перечисляются.

Сервер строит READ ONLY REPEATABLE READ снимок собственных зависимостей группы, урока или теста. Есть12 категорий препятствий: связанные группы, чужое владение, общий каталог, история тестов и уроков, история ЕНТ, общие вопросы/контексты, общая генерация, отсутствие членства учеников, внешние предоставления доступа и медиа. Учтены оба способа связей вопросов с тестами и изображения в пояснениях. Содержимое чужих зависимостей и их ID не раскрываются.

Оба флага `execution_allowed` и `tenant_enforcement_ready` всегда false. Нет apply endpoint, автоматического backfill, изменения владельцев, членства или публичности. Отсутствие замечаний не является готовностью к переносу. Общий каталог сохраняется отдельно согласно решению пользователя.

API: GET `/api/v1/organizations/:id/transfers/candidates`, POST `/api/v1/organizations/:id/transfers/preflight`. Требуются JWT и active owner/admin целевой организации. Чужой/отсутствующий корень возвращает одинаковый404 до counts; участник без прав403. Проверка не обращается к внешним image URLs и не читает локальные пути из контента.

Tenant scope для всех учебных агрегатов и child routes, блокировка обхода через legacy API, scoped списки/чтения/изменения/attempts/ЕНТ и защищённые файлы. Текущее API предварительной проверки нельзя использовать как разрешение на изменение данных.
