# ent-ready — UX/UI: спокойная учебная среда

23.10.2026. Основание: [передача бизнес-аналитика](01-business-research.md), обязательный выбор пользователя A и [аудит исходников](redesign-ux-notes.md). Это проектная спецификация, не реализованный интерфейс. Текущий сайт и визуальный UI аналогов не просматривались; выводы о текущем продукте основаны на коде, аналоги — на публичной текстовой структуре. Пользовательские исследования и соответствие WCAG не подтверждены.

## Цель и границы

Ученик должен найти назначение или выбрать предметную тренировку/ЕНТ, понимать сохранение ответа и корректно читать результат. Учитель должен найти группу или тест, создать черновик и отличать публикацию от публичного доступа. Сохраняем маршруты, права, модель баллов и текущие правила прохождения. Не вводим рекомендации, рост прогресса, рейтинги, гостевой вход, уведомления, серверные черновики и восстановление обычного теста.

Структурные выводы BA применены так: iTest → отдельная подготовка ЕНТ; Daryn → локальный поиск и no-results; Testportal/Kahoot → разные намерения двух ролей. Ни фирменные стили, ни закрытые кабинеты не копируются.

## Потоки и карта

- Ученик: `/student` → назначенный `/student/tests/:id` либо предмет `/student/subjects/:id` → старт → ответы → finish → итог → `/student/results/:attemptId`. ЕНТ доступен отдельно через `/student/ent`; без двух профильных предметов перейти в профиль. Не добавлять переход «Продолжить обычный тест».
- Учитель: `/teacher` (мои группы) → `/teacher/groups/:id`; навигация → `/teacher/tests` → существующая форма создания → `/teacher/tests/:id` → предусмотренные публикация и результаты. Не помещать публикацию в форму создания, если это меняет workflow.
- До desktop 768 px — нижняя навигация пяти существующих разделов; выше — sidebar. Во время обычного теста снизить визуальную активность оболочки, но сохранить существующий выход. Явно предупредить о возможной потере локального состояния при выходе/перезагрузке; подтверждение не заменяет серверное восстановление.

## Система оформления

Текущие Button/Input/Card, Tailwind и Geist остаются основой. Новую UI-библиотеку не вводим. Все цвета через semantic токены; логотип ENT использует foreground вместо hardcoded white. Синий — основной action, бирюза логотипа — небольшой брендовый акцент. Предметы получают одинаковую мягкую подложку, различаются текстом/символом, а не радугой насыщенных плиток.

Radius card 16px, input/button 10px; stroke 1px; тень только у меню/диалога, без тени каждой карточки. Шкала отступов 4/8/12/16/24/32/48. Desktop container максимум 1120px, sidebar 224px, gutter 32px. Основной рабочий текст максимум 720px; форма и тест до 760px, без растяжения строки на весь монитор. На mobile gutter 16px, карточки 16px, одна колонка. Предметы: 3 desktop / 2 mobile, при длинных заголовках переносить без обрезки. На 320px допускается 1 колонка. Нижняя панель имеет safe-area-inset-bottom, main такой же резерв плюс высота панели. Кнопки/радио не менее 44×44px, видимый focus 2px с offset 3px. Уменьшенные движения при prefers-reduced-motion.

## Экранные решения

### 1. Главная ученика

Заголовок «Мои тесты», краткая подпись; первым блоком «Назначенные тесты», затем «Тренировка по предметам» с подписанным поиском, рядом спокойная ссылка на ЕНТ. Назначение: title, max_attempts, time_limit только если нормализован и >0, действие «Открыть тест». Не показывать срок, выполненность и оставшиеся попытки без соответствующего поля. В одной карточке одно действие. Не дублировать тесты при назначении через несколько групп: дедупликация по id после подтверждения архитектора.

Пустые назначения: «Назначенных тестов пока нет. Можно выбрать предмет для тренировки». Отсутствие предметов после успешного запроса отличается от поиска без совпадений: «Ничего не найдено» + «Сбросить поиск». Назначения, предметы и группы могут ошибаться независимо: не скрывать весь экран из-за одного блока.

### 2. Подготовка ЕНТ

Заголовок, «Состав пробного теста» в списке пяти предметов, время/вопросы/максимум только из подтверждённой конфигурации. В текущем frontend есть hardcoded 120/240/140; архитектор обязан проверить server rules до включения этих чисел в ТЗ. До этого прототип показывает состав без численного обещания. Два профильных предмета и понятный линк «Выбрать в профиле» при отсутствии. Не давать disabled CTA без объяснения рядом. История использует реальные attempts; отметка «В процессе» допустима только для существующего ENT finished_at=null, не переносить это обещание на обычный тест.

### 3. Обычный тест

До старта: название, максимум попыток как правило (не «осталось»), лимит времени при наличии, «Начать тест». Ошибка недоступности отделяется от загрузки. Во время: компактный заголовок, вопрос X из Y, время (если есть), полоса обозначает **положение**, не количество верных/сохранённых ответов. Один вопрос, radio group с legend и MathText; перенос формул через локальный overflow, без горизонтального скролла всей страницы.

Под ответами одно устойчивое место под статус «Сохраняем ответ… / Ответ сохранён / Ответ не сохранён. Повторить». «Сохранён» только после success последней актуальной записи. Архитектор задаёт порядок запросов при быстрой смене ответов, блокирование/очередь и finish после pending записей. До этого UI не может гарантировать сохранение.

Сохраняем текущую последовательность: «Далее» только после выбора, финальный «Завершить тест» после всех выборов, но также без pending/error записей. Не добавлять произвольную навигацию, пропуски и изменение правил сдачи. «Назад» возвращает предыдущий вопрос. Ноль времени: состояние «Время вышло. Отправляем результат…»; ошибка завершения — явное сообщение и повтор, без ложного результата. Единственный корректный таймер/серверная граница — обязательная техническая задача, не косметика.

### 4. Итог и разбор

Верхняя карточка: «Тест завершён», score/max_score баллов; подпись «N% от максимального балла». Если max_score отсутствует/нулевой, не выводить деление и процент. Далее либо разбор, либо нейтральный замок «Разбор пока недоступен» с разрешённым сервером deadline. При can_see_answers=false или review 403 не строить и не загружать скрытые correct answers ради макета. Итоговый балл и доступность разбора независимы. В разборе явные слова «Верно», «Неверно», «Ваш ответ», «Правильный ответ», а не только красный/зелёный. Контекстный выход «К результатам».

### 5. Учитель: мои группы

Это рабочий список существующих групп, **не новый аналитический dashboard**. Заголовок + «Создать группу»; карточки name/city/school/category и «Открыть группу». Нет чисел участников, активности или среднего балла. Создание в раскрытой панели перед списком: название, город, школа/организация, category как подписанная радиогруппа; pending/error/success. Cancel не очищает непредупреждённо введённый текст. Успех фокусирует новую запись/сообщение, не пропадает без обратной связи.

### 6. Учитель: тесты

Заголовок + «Создать тест», существующий фильтр предмета с label; локальная фильтрация, затем группировка по предмету. В строке: title, «Черновик/Опубликован» по is_published, «Публичный/Не публичный» по is_public (точную формулировку подтверждает архитектор), правило попыток и время. Не отождествлять is_public с is_published. На mobile строки становятся карточками, без сокращения длинного названия. Создание сохраняет title/group_id/topic_id/max_attempts/time_limit/is_public/deadline; не добавлять новые обязательные поля и не менять null-семантику. Из карточки — существующий editor; результаты только по существующему маршруту и правам.

## Общие состояния и доступность

Loading: скелетон без имитации данных + sr-only «Загрузка»; не показывать нулевые метрики. Error: причина в безопасной формулировке + «Повторить», сохранять ввод, фокус не прыгать. Denied/404: «Материал недоступен» и безопасный путь назад, без закрытого названия/ответов. Expired auth: существующая обработка сессии, без обещания восстановить попытку. Success записи: role=status; ошибка role=alert, не каждый тик таймера. Переход вопроса фокусирует legend; изменение фильтра сохраняет focus и объявляет число найденных загруженных элементов. Все icon-only кнопки имеют accessible name; active navigation aria-current=page. Input связывает error через aria-describedby и aria-invalid. Dialog требует focus trap и возврат focus; предпочтительна inline форма без лишнего модального слоя.

## Прототип и передача

[Автономный HTML](02-redesign-prototype.html) содержит шесть экранов, переключение темы и состояний на искусственных данных. Toolbar — инструмент ревью, не продуктовая функция. Никакой сети, реальной авторизации/интеграции/создания записей нет. Кнопки навигации и переключатели демонстрируют композицию; реальные create/submit/start не имитируются как успешная серверная операция. Прототип не обещает resume или backend функции.

Архитектору передать как блокеры до реализации: legacy time_limit типы (реальный JSON number|null); локальный timer estimate и серверная проверка expiry; контракт последовательности answer/finish; действительные правила ЕНТ; семантика публичности; действительная доступность result/denied. Frontend не менять до его ТЗ.

Приёмка реализации: 360/768/1440px, светлая/тёмная, клавиатура; длинный title, пустой/error запрос, медленная запись, failed answer и finish, нулевой max_score, locked review, 2 профиля отсутствуют, обе роли. Проверить формулы, отсутствие перекрытия mobile nav, контраст и фокус; провести build/lint по правилам проекта и независимые сценарии tester. Ни эти runtime-проверки, ни пользовательское сравнение текущего сайта с прототипом на данном этапе не выполнены.


Уточнения архитектора после проверки backend: groupResponse не содержит description; карточка использует name, city, school, category при наличии. pgtype.Int2 сериализуется number|null, pgtype.Text — string|null. Обычный StartAttempt не возвращает started_at/server deadline: локальное время только оценочное, с подписью «Примерное оставшееся время»; точный серверный countdown требует отдельного расширения контракта и не блокирует косметический MVP. Источник истины срока — сервер. /attempts/my возвращает ограниченный finished-only список без total; глобальные метрики прогресса не выводить. is_public=false обозначать «Не публичный», без предположения о назначенной аудитории. Прототип использует только искусственные значения, реальные id/пользователи не включены.


Контраст элементов управления: декоративная граница border остаётся мягкой; отдельный control-border #7B8BA0 light / #7A8DA9 dark используется у input/select и границы вариантов radio. Численный расчёт координатора для границ на card: 3.48:1 / 4.61:1; это расчёт токенов, не проверка отрисованного интерфейса. В прототипе Далее включается только в saved, а expired блокирует выбор ответа и показывает демонстрацию отправки результата без реального запроса.
